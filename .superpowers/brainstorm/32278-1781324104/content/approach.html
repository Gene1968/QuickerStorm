A

Semantic steps (recommended)

Name tokens by role. Dark mode uses low steps for surfaces, high steps for text. Light mode swaps them. Two explicit assignments — no math.

--surface: rufous-10
--surface-raised: rufous-20
--text: rufous-90
--text-subtle: rufous-70
--border: rufous-30
/* light mode: */
--surface: rufous-90
--text: rufous-10
✓ Readable, predictable, easy to hand-edit
✓ Each step is a real swatch you can see
✓ Works with existing Tailwind channel-triplets
✗ Light mode requires re-stating each var
✗ ~12 vars in :root, ~12 in html.light
B

Palette steps + single override

Define the full 10-step palette in @theme. Semantic tokens pick a step number. Light mode only redefines the step assignments — not the palette itself.

/* @theme (once) */
--color-primary-1: #200B05
--color-primary-9: #ECD7D1
/* semantic layer */
--surface: var(--color-primary-1)
--text: var(--color-primary-9)
/* light: swap refs only */
--surface: var(--color-primary-9)
--text: var(--color-primary-1)
✓ Palette defined once, themes swap references
✓ Easy to replace entire palette (one block)
✓ Radix UI / shadcn style — proven pattern
✗ Two layers of indirection (step → semantic)
✗ Slightly more vars total
C

oklch lightness inversion

Store each color as oklch(L C H). Light mode auto-computes the complement: L → (1 - L). Pure math — no second theme block needed.

/* single definition */
--surface: oklch(12% .08 30)
/* light auto-flips to: */
--surface: oklch(88% .08 30)

--text: oklch(92% .04 30)
--text: oklch(8% .04 30)
✓ Minimal CSS — no html.light block at all
✓ Mathematically consistent contrast pairs
✗ Hardest to debug (can't see real hex values)
✗ Some hues don't perceptually invert cleanly
✗ Requires CSS custom property math support
